## 1. 团队概述

本团队由4人组成，采用Scrum敏捷开发模式。团队按"角色互补、职责清晰"原则分工：队长负责后端架构与AI核心，前端专家负责所有用户界面，后端/业务逻辑负责数据库与业务API，测试/运维负责质量保障与部署。每位成员在各自领域承担完整的设计、开发与测试职责。

## 2. 模块分工详情

### 2.1 队长 — 后端核心架构与AI集成

**职责**：项目管理 + 后端核心架构 + AI服务集成

**项目管理工作**：
- Scrum Master / Product Owner 角色
- 项目整体进度把控与风险管理
- 代码审查（所有PR至少队长审查）
- 团队沟通协调、会议组织

**后端架构工作**：
- FastAPI项目初始化与分层架构设计
- 数据库连接池配置（SQLAlchemy）
- Redis缓存配置
- API网关设计（统一路由、认证中间件、异常处理）
- 模块间接口定义和规范化
- JWT认证机制实现（security.py + deps.py）
- 用户认证API开发（注册/登录/密码修改）

**AI核心工作**：
- AI API集成（OpenAI/通义千问，支持流式）
- RAG语义搜索架构设计与向量数据库（ChromaDB）集成
- Few-Shot提示词模板库设计与管理
- SSE流式文案生成后端实现
- 选题推荐算法实现（RAG + Few-Shot）
- AI配图生成接口集成

**技术要求**：
- 后端：FastAPI + SQLAlchemy + ChromaDB + OpenAI API
- 认证：JWT + bcrypt
- 流式：SSE / StreamingResponse

**交付成果**：
- 完整的后端框架与API网关
- AI内容生成服务（选题/文案/配图）
- 用户认证系统
- API文档（Swagger）

### 2.2 前端专家 — 全部前端界面与交互

**职责**：前端框架搭建 + 所有页面开发

**框架工作**：
- Vue 3项目初始化和配置
- Element Plus组件库集成
- Pinia状态管理配置
- Vue Router路由配置（含路由守卫）
- 前端API请求封装（Axios拦截器 + Token管理）
- 全局样式配置与响应式布局

**页面开发工作**：
- 登录/注册页面（Login.vue / Register.vue）
- 仪表盘页面（Dashboard.vue）— 核心数据卡片、平台饼图、趋势折线图
- 素材管理页面（MaterialList.vue / MaterialForm.vue）
- 标签管理组件
- AI选题生成页面（TopicGenerate.vue）
- AI文案生成页面（ContentGenerate.vue）— SSE流式渲染
- 平台适配页面（PlatformAdapter.vue）— 实时预览
- 创作记录列表页面（RecordList.vue）
- 版本对比页面（VersionCompare.vue）
- 统计分析页面 — ECharts图表集成（折线图、柱状图、饼图、词云）
- 个人信息页面（UserProfile.vue）
- 公共组件（Header.vue、Sidebar.vue、Layout.vue）

**测试工作**：
- 前端功能测试
- 响应式布局测试
- SSE流式渲染兼容性测试

**技术要求**：
- 前端：Vue.js 3 + Element Plus + Pinia + Vue Router + Axios + ECharts + Quill
- 构建工具：Vite
- 代码规范：ESLint + Prettier

**交付成果**：
- 完整的前端应用
- 所有页面和公共组件
- 前端技术文档

### 2.3 后端/业务逻辑 — 数据库设计与业务API

**职责**：数据库设计 + 业务层API开发

**数据库设计工作**：
- 数据表设计（users, user_profiles, materials, tags, material_tags, records, versions）

**素材管理API开发**：

**平台适配API开发**：
- 抖音格式适配逻辑实现（标题截断、标签格式化）

**统计分析API开发**：

- 后端：FastAPI + SQLAlchemy + Alembic

**交付成果**：
- 完整的数据库模型与迁移脚本

### 2.4 测试/运维专家 — 质量保障与部署

## 3. 时间安排（14周课程周期）

### 3.1 第1-2周：团队组建与选题
- **所有成员**：项目调研、选题讨论、开发环境配置
- **队长**：组织选题评审，撰写《选题及团队组建报告》
- **测试/运维**：搭建Git仓库、建立协作规范

### 3.2 第2-3周：需求分析
- **队长**：组织需求评审会议，确定技术方案
- **后端/业务逻辑**：数据库概念设计（ER图）、数据字典初稿
- **前端专家**：UI原型设计，确定页面流转
- **测试/运维**：撰写《需求规格说明书》，汇总需求文档

### 3.3 第3-4周：系统设计
- **队长**：API网关设计、接口规范定义、认证机制设计
- **后端/业务逻辑**：详细数据库设计（7张表）、Alembic迁移
- **前端专家**：组件架构设计、路由规划、状态管理方案
- **测试/运维**：撰写《系统设计说明书》，准备测试策略

### 3.4 第4-6周：核心模块开发（Sprint 1）
- **队长**：FastAPI框架搭建、JWT认证实现、用户API、AI API集成
- **后端/业务逻辑**：素材管理API、标签管理API、文件上传API
- **前端专家**：登录/注册页面、素材管理页面、主界面布局
- **测试/运维**：搭建Docker开发环境、用户认证测试

### 3.5 第6-8周：AI与创作模块开发（Sprint 2）
- **队长**：RAG语义搜索集成、SSE流式生成、Few-Shot Prompt模板库
- **后端/业务逻辑**：创作记录API、版本管理API、导出API
- **前端专家**：AI选题页面、SSE流式文案页面、创作记录页面、版本对比页面
- **测试/运维**：AI生成功能测试、API接口测试

### 3.6 第8-10周：适配与可视化开发（Sprint 3）
- **队长**：AI配图生成接口集成、Prompt调优
- **后端/业务逻辑**：平台适配算法、合规审计逻辑、统计分析API
- **前端专家**：平台适配页面（预览）、统计分析页面（ECharts）、仪表盘页面
- **测试/运维**：平台适配测试、统计功能测试

### 3.7 第10-12周：集成测试与优化（Sprint 4）
- **所有成员**：前后端联调、Bug修复
- **队长**：性能优化、代码审查
- **前端专家**：UI优化、响应式适配
- **后端/业务逻辑**：数据库查询优化、接口完善
- **测试/运维**：系统集成测试、性能测试、安全测试

### 3.8 第12-14周：交付与答辩
- **队长**：项目总结、答辩PPT准备
- **前端专家**：功能演示录制
- **后端/业务逻辑**：API文档最终审查
- **测试/运维**：Docker生产部署、最终测试报告、文档汇总打包

## 4. 协作机制

### 4.1 沟通方式

**Scrum站会**
- 频率：每周3次（周一、周三、周五）
- 时长：15分钟
- 内容：上次完成了什么 → 本次计划做什么 → 遇到什么阻塞

**在线协作**
- 即时通讯：微信群/飞书
- 代码托管：GitHub
- 任务跟踪：GitHub Issues + Projects看板

### 4.2 代码审查

- 频率：每完成一个功能模块提交PR
- 要求：至少1人审查（队长必审）
- 规范：Conventional Commits（feat/fix/docs/refactor）

### 4.3 分支策略

- main：主分支，稳定版本
- develop：开发分支
- feature/*：功能分支（feature/ai-sse, feature/platform-adapter等）
- bugfix/*：修复分支

### 4.4 代码规范

**前端**：ESLint + Prettier，组件PascalCase，文件kebab-case
**后端**：PEP 8，函数snake_case，类PascalCase，添加类型注解

## 5. 质量保证

### 5.1 测试策略
- 单元测试：Pytest（后端核心逻辑）
- API测试：Postman集合覆盖所有端点
- 集成测试：模块间联调测试
- 性能测试：核心功能响应<2秒，SSE首Token<3秒

### 5.2 安全检查
- SQL注入防护（ORM参数化查询）
- XSS防护（JSON API + 前端转义）
- JWT Token安全（HS256、30分钟有效期）
- 密码bcrypt加密
- API Key .env管理

## 6. 风险管理

| 风险 | 概率 | 影响 | 对策 |
| :--- | :--- | :--- | :--- |
| AI集成难度大 | 中 | 高 | 规则引擎备选；多AI服务商 |
| RAG检索效果差 | 中 | 中 | 提前验证Embedding质量 |
| 开发进度延迟 | 高 | 高 | 优先核心功能；Scrum跟踪 |
| 4人团队工作量大 | 高 | 中 | 合理分工；复用开源组件 |
