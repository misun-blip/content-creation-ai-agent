> **文档版本**：1.0 | **编制日期**：2026-05-27 | **编制人**：运维组

## 1. 环境要求

| 组件 | 最低版本 | 说明 |
|------|----------|------|
| Docker | 20.10+ | 容器运行时 |
| Docker Compose | V2（`docker compose`） | 编排工具 |
| Python | 3.11+ | 仅本地开发时需要 |
| Git | 2.x | 代码拉取 |

> **注意**：生产环境只需 Docker + Docker Compose，无需在宿主机安装 Python/MySQL/Redis。

## 2. 首次部署步骤

### 2.1 克隆代码仓库

```bash
git clone <仓库地址>
cd content-creation-ai-agent
```

### 2.2 配置 `.env` 环境变量

```bash
cp backend/.env.example backend/.env
```

用编辑器打开 `backend/.env`，按下方说明修改关键配置：

```env
# ===== 必须修改 =====
SECRET_KEY=<随机32位字符串，可用 openssl rand -hex 32 生成>
DATABASE_URL=mysql+pymysql://content_ai:content_ai_password@mysql:3306/content_ai_agent

# ===== 按需修改 =====
DEBUG=false                          # 生产环境务必设为 false
REDIS_URL=redis://redis:6379/0

# ===== AI 服务（至少填一个）=====
AI_API_KEY=<你的 API Key>
AI_API_BASE=https://api.chatanywhere.tech/v1
```

完整配置项说明见 [第 3 节](#3-env-配置项说明)。

### 2.3 构建后端镜像

```bash
docker compose build backend
```

### 2.4 启动全部服务

```bash
# 启动数据库 + Redis + 后端（后台运行）
docker compose up -d mysql redis backend
```

等待约 30 秒后，检查服务健康状态：

```bash
docker compose ps
```

预期输出（`STATUS` 列均为 `Up` 或 `healthy`）：

```
NAME                  STATUS              PORTS
content_ai_mysql      Up (healthy)        3306/tcp
content_ai_redis      Up (healthy)        6379/tcp
content_ai_backend    Up                  0.0.0.0:8000->8000/tcp
```

### 2.5 数据库初始化

**方式 A：使用 Docker Exec（推荐）**

```bash
# 进入后端容器执行迁移
docker compose exec backend alembic upgrade head

# 写入初始数据（可选）
docker compose exec backend python app/initial_data.py
```

**方式 B：本地执行（需安装依赖）**

```bash
cd backend
pip install -r requirements.txt
alembic upgrade head
python app/initial_data.py
```

### 2.6 启动前端与 Nginx

```bash
# 启动全部服务（含前端和 Nginx 反向代理）
docker compose up -d
```

访问 `http://localhost` 即可打开前端页面。  
访问 `http://localhost/docs` 查看后端 API 文档。

## 3. `.env` 配置项说明

| 配置项 | 默认值 | 说明 | 是否必须修改 |
|--------|--------|------|-------------|
| `APP_NAME` | 内容创作AI-Agent | 应用名称，显示在 API 文档标题 | 否 |
| `APP_VERSION` | 1.0.0 | 应用版本号 | 否 |
| `DEBUG` | true | `false` = 生产模式，关闭自动重载和详细错误 | **生产必须改** |
| `DATABASE_URL` | sqlite:///./test.db | 数据库连接串，Docker 部署时改为 MySQL | **必须** |
| `REDIS_URL` | redis://localhost:6379/0 | Redis 连接串，Docker 部署时改为服务名 | **必须** |
| `SECRET_KEY` | dev-secret-key-... | JWT 签名密钥，生产环境必须使用随机强密钥 | **必须** |
| `ALGORITHM` | HS256 | JWT 算法，通常无需修改 | 否 |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 30 | Token 过期时间（分钟） | 否 |
| `AI_API_KEY` | — | AI 服务的 API Key | **必须** |
| `AI_API_BASE` | https://api.openai.com/v1 | AI 服务接口地址 | **必须** |
| `OPENAI_API_KEY` | — | OpenAI 兼容 Key（与 AI_API_KEY 二选一） | 视情况 |

## 4. 常用运维命令

### 查看实时日志

```bash
docker compose logs -f backend     # 后端日志
docker compose logs -f nginx       # Nginx 访问日志
docker compose logs -f mysql       # MySQL 日志
```

### 重启单个服务

```bash
docker compose restart backend
```

### 更新代码后重新部署

```bash
git pull
docker compose build backend
docker compose up -d backend
```

### 执行数据库迁移

```bash
# 查看当前迁移版本
docker compose exec backend alembic current

# 升级到最新版本
docker compose exec backend alembic upgrade head

# 回滚一步
docker compose exec backend alembic downgrade -1
```

### 停止服务

```bash
docker compose down           # 停止并移除容器（数据保留）
docker compose down -v        # 同时删除数据卷（⚠️ 会清空数据库）
```

## 5. 生产环境注意事项

1. **SECRET_KEY**：使用 `openssl rand -hex 32` 生成，切勿使用默认值
2. **数据库密码**：修改 `docker-compose.yml` 中 `MYSQL_PASSWORD` 和 `DATABASE_URL`
3. **关闭 DEBUG**：`DEBUG=false`，避免详细堆栈信息泄露
4. **HTTPS**：建议在 Nginx 配置 SSL 证书（Let's Encrypt 免费证书）
5. **备份**：定期备份 `mysql_data` 数据卷：
   ```bash
   docker compose exec mysql mysqldump -u root -p content_ai_agent > backup_$(date +%F).sql
   ```

## 6. 服务架构说明

```
外部请求
    │
    ▼
[Nginx :80]
    ├── /          → [frontend :3000]  前端 Vue 应用
    ├── /api/      → [backend :8000]   FastAPI 后端
    ├── /api/v1/ai/stream → [backend]  SSE 流式（禁用缓冲）
    └── /docs      → [backend]         Swagger 文档
         │
    [backend :8000]
         ├── MySQL :3306
         └── Redis :6379
```

## 7. 故障排查

| 现象 | 可能原因 | 解决方法 |
|------|----------|----------|
| 后端容器不断重启 | `.env` 未配置或 MySQL 未就绪 | `docker compose logs backend` 查看错误 |
| 数据库连接失败 | `DATABASE_URL` 中主机名错误 | Docker 内使用服务名 `mysql`，不能用 `localhost` |
| AI 接口 500 错误 | API Key 无效或余额不足 | 检查 `AI_API_KEY` 配置 |
| Nginx 502 Bad Gateway | 后端服务未启动 | `docker compose ps` 检查 backend 状态 |
| SSE 流式响应断开 | Nginx `proxy_read_timeout` 不足 | 确认 `nginx/nginx.conf` 中 SSE location 已配置 |
