## 1. 系统体系架构

### 1.1 总体架构

本系统采用 **B/S架构（Browser/Server）** 下的 **前后端分离** 模式，整体分为四层：**表示层、业务逻辑层、数据访问层、数据存储层**。系统通过 Docker Compose 进行容器化编排部署，Nginx 作为反向代理统一入口。

```

│                     Nginx 反向代理 (端口 80)                      │
```

### 1.2 技术选型

| 层次 | 技术 | 说明 |
|------|------|------|
| **前端** | Vue.js 3 + Vite | 组合式API，高效HMR开发体验 |
| **UI框架** | Element Plus | 完善的企业级Vue3组件库 |
| **状态管理** | Pinia | 轻量类型安全的Vue状态管理 |
| **HTTP客户端** | Axios | 支持拦截器、自动Token注入 |
| **数据可视化** | ECharts | 丰富的图表类型 |
| **后端框架** | Python FastAPI | 异步高性能，自动OpenAPI文档 |
| **ORM** | SQLAlchemy 2.x | 成熟稳定，连接池支持 |
| **数据库迁移** | Alembic | 支持自动生成迁移脚本 |
| **认证** | JWT (python-jose) | 无状态，前后端分离友好 |
| **密码加密** | passlib + bcrypt | 行业标准抗暴力破解 |
| **数据库** | MySQL 8.0 | 关系型，事务支持 |
| **缓存** | Redis 6.0 | 高性能键值存储 |
| **部署** | Docker + Nginx | 容器化隔离，反向代理 |
| **AI服务** | OpenAI API (GPT-3.5-turbo) | 通过ChatAnywhere转发调用 |

- 每个Formatter继承`BaseFormatter`抽象基类，实现`format_title()`、`format_content()`、`format_tags()`三个标准化接口
- 适配过程中产生的warnings（如字数超限）和suggestions（如自动生成标题）会随结果一起返回前端

## 4. 复杂功能算法设计

### 4.1 AI内容质量评估算法

```
算法名称: 内容质量评估 (evaluate_content)
输入: content(文案内容), topic(主题), target_length(目标字数)
输出: score(评分0-100), suggestions(改进建议列表)

伪代码:
────────────────────────────────────────
FUNCTION evaluate_content(content, topic, target_length):
    score ← 100
    suggestions ← []

    // 步骤1: 文本长度检查
    actual_length ← LENGTH(content)
    IF actual_length < target_length × 0.7 THEN
        score ← score - 15
        suggestions.ADD("字数严重不足，建议丰富细节")
    ELSE IF actual_length > target_length × 1.3 THEN
        score ← score - 5
        suggestions.ADD("字数偏多，建议精简冗余信息")
    END IF

    // 步骤2: 关键词覆盖度检查
    keywords ← SPLIT(topic, [',', '，', ' '])
    missing_keywords ← []
    FOR EACH kw IN keywords:
        IF kw NOT IN content THEN
            missing_keywords.ADD(kw)
        END IF
    END FOR
    IF missing_keywords NOT EMPTY THEN
        penalty ← MIN(20, LENGTH(missing_keywords) × 5)
        score ← score - penalty
        suggestions.ADD("未覆盖核心关键词: " + JOIN(missing_keywords))
    END IF

    // 步骤3: 敏感词/违禁词检测
    sensitive_words ← ["第一", "最高级", "国家级", "包治百病",
                       "绝对", "100%", "极品", "逢考必过"]
    found_sensitive ← []
    FOR EACH word IN sensitive_words:
        IF word IN content THEN
            found_sensitive.ADD(word)
        END IF
    END FOR
    IF found_sensitive NOT EMPTY THEN
        score ← score - 30
        suggestions.ADD("⚠️ 包含疑似营销违禁词，存在限流风险")
    END IF

    // 步骤4: 兜底处理
    score ← MAX(0, score)
    IF score >= 95 THEN
        suggestions.ADD("🎉 文案质量非常棒，可直接发布")
    END IF

    RETURN {score, suggestions}
END FUNCTION
────────────────────────────────────────
```

### 4.2 平台内容格式化算法（策略模式）

```
算法名称: 平台内容适配 (adapt_content)
输入: content, platform, title(可选), tags(可选)
输出: FormatResult{title, content, tags, preview, warnings, suggestions}

伪代码:
────────────────────────────────────────
FUNCTION adapt_content(content, platform, title, tags):
    // 1. 策略选择
    config ← GET_PLATFORM_CONFIG(platform)
    formatter ← FORMATTER_MAP[platform].NEW(config)
    // FORMATTER_MAP = {douyin→DouyinFormatter,
    //                  xiaohongshu→XiaohongshuFormatter,
    //                  wechat→WechatFormatter}

    warnings ← []
    suggestions ← []

    // 2. 标题格式化
    IF title IS NULL THEN
        title ← EXTRACT_FIRST_SENTENCE(content)[:20]
        suggestions.ADD("已自动生成标题")
    END IF
    (formatted_title, title_warnings) ← formatter.format_title(title)
    warnings.EXTEND(title_warnings)

    // 3. 正文格式化 (各平台差异化处理)
    (formatted_content, content_warnings) ← formatter.format_content(content)
    warnings.EXTEND(content_warnings)

    // 4. 标签格式化
    IF tags IS NULL THEN
        tags ← DEFAULT_TAGS[:3]  // 默认提取热点标签
        suggestions.ADD("已自动提取标签")
    END IF
    (formatted_tags, tag_warnings) ← formatter.format_tags(tags)
    warnings.EXTEND(tag_warnings)

    // 5. 生成预览
    IF platform == "wechat" THEN
        preview ← title + "\n\n" + content  // 微信不显示标签
    ELSE
        preview ← title + "\n\n" + content + "\n\n" + JOIN(tags, ' ')
    END IF

    RETURN FormatResult(formatted_title, formatted_content,
                        formatted_tags, preview, warnings, suggestions)
END FUNCTION
────────────────────────────────────────
```

## 6. 接口设计

### 6.1 接口总览

所有接口统一前缀 `/api/v1`，响应格式：`{code: int, message: str, data: any}`

| 模块 | 前缀 | 认证 |
|------|------|------|
| 认证 | /api/v1/auth | 否（注册/登录）|
| 素材管理 | /api/v1/materials | 是 |
| 标签 | /api/v1/tags | 是 |
| AI生成 | /api/v1/ai | 部分 |
| 平台适配 | /api/v1/adapter | 是 |
| 创作记录 | /api/v1/records | 是 |
| 统计分析 | /api/v1/statistics | 是 |
| 文件上传 | /api/v1/uploads | 是 |
| 仪表盘 | /api/v1/dashboard | 是 |

### 6.2 核心接口详细设计

#### 认证接口

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| POST | /auth/register | 用户注册 | `{username, email, password}` | `{code, message, data: {user}}` |
| POST | /auth/login | 用户登录 | `{username, password}` | `{code, message, data: {access_token, user}}` |
| GET | /auth/me | 获取当前用户 | - | `{code, message, data: {user}}` |
| PUT | /auth/password | 修改密码 | `{old_password, new_password}` | `{code, message}` |

#### AI生成接口

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| POST | /ai/topics | 生成选题 | `{keywords, industry, platform, count}` | `{data: {topics: [{title, description, platform}]}}` |
| POST | /ai/content | 生成文案 | `{topic, length, style, platform}` | `{data: {content: str}}` |
| POST | /ai/evaluate | 质量评估 | `{content, topic, target_length}` | `{data: {score: int, suggestions: []}}` |

#### 平台适配接口

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| POST | /adapter/format | 内容适配 | `{content, platform, title?, tags?, auto_format}` | `{data: {title, content, tags, preview, warnings, suggestions}}` |
| GET | /adapter/platforms | 获取平台列表 | - | `{data: [{code, name, limits}]}` |

#### 创作记录接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /records | 记录列表（支持分页/筛选/搜索） |
| POST | /records | 创建记录 |
| GET | /records/{id} | 记录详情（含版本列表） |
| PUT | /records/{id} | 更新记录 |
| DELETE | /records/{id} | 删除记录 |
| POST | /records/{id}/versions | 创建新版本 |
| GET | /records/{id}/versions | 获取版本列表 |
| GET | /records/{id}/export | 导出记录（TXT/MD/JSON） |

### 6.3 前端API封装

前端通过Axios实例统一管理请求，核心设计：

- **请求拦截器**：自动从Pinia Store读取Token并注入`Authorization`头
- **响应拦截器**：统一处理`code !== 200`的业务错误、401自动登出、网络异常友好提示
- **代理转发**：Vite开发环境通过`vite.config.js`中的proxy配置将`/api`请求转发至`localhost:8000`

### 8.3 交互设计要点

1. **路由守卫**：未登录用户访问受保护页面自动重定向至登录页；已登录用户访问登录/注册页自动重定向至首页
2. **Token管理**：Pinia Store持久化存储Token，Axios拦截器自动注入，401响应触发自动登出
3. **页面标题**：路由切换时自动更新 `document.title` 为 `{页面名称} - 内容创作AI-Agent`
4. **组件库**：使用Element Plus提供的表单、表格、对话框、消息提示等组件，确保UI一致性
5. **公共组件**：`BaseButton.vue`（通用按钮）、`BaseCard.vue`（卡片容器）、`Loading.vue`（加载动画）
6. **数据可视化**：统计分析页使用ECharts渲染折线图、柱状图、饼图等
7. **响应式布局**：侧边栏可折叠，内容区自适应宽度
