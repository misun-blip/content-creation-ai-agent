## 1. 项目概述
### 1.1 项目背景
随着自媒体行业的快速发展，内容创作已成为自媒体从业者的核心挑战。传统的内容创作方式耗时费力，且难以保证作品的质量与吸引力。本项目旨在开发一款轻量化的AI辅助内容创作工具，帮助自媒体从业者提高创作效率，降低创作门槛。
### 1.2 项目定位
定位为"轻量化、易上手的流媒体/自媒体营销内容辅助工具"，聚焦"营销素材智能生成、内容格式快速适配、创作记录留存与基础数据统计"核心需求，适配应届生独立完成，重点验证AI辅助创作逻辑与营销场景落地能力。

## 4. 数据库设计
### 4.1 数据库表结构
#### 4.1.1 用户表 (users)
```sql
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_username (username),
    INDEX idx_email (email)
);
```
#### 4.1.2 分类表 (categories)
```sql
CREATE TABLE categories (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    parent_id INT NULL,
    description TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (parent_id) REFERENCES categories(id) ON DELETE SET NULL,
    INDEX idx_name (name)
);
```
#### 4.1.3 素材表 (materials)
```sql
CREATE TABLE materials (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    category_id INT,
    type ENUM('template', 'image', 'video', 'audio', 'document') NOT NULL,
    name VARCHAR(255) NOT NULL,
    content TEXT,
    file_path VARCHAR(500),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE SET NULL,
    INDEX idx_user_id (user_id),
    INDEX idx_type (type),
    INDEX idx_category_id (category_id)
);
```
#### 4.1.4 标签表 (tags)
```sql
CREATE TABLE tags (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) UNIQUE NOT NULL,
    usage_count INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_name (name)
);
```
#### 4.1.5 素材标签关联表 (material_tags)
```sql
CREATE TABLE material_tags (
    id INT AUTO_INCREMENT PRIMARY KEY,
    material_id INT NOT NULL,
    tag_id INT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (material_id) REFERENCES materials(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE,
    UNIQUE KEY uk_material_tag (material_id, tag_id),
    INDEX idx_material_id (material_id),
    INDEX idx_tag_id (tag_id)
);
```

> 说明：标签关系仅通过 `material_tags` 表维护，`materials` 表不再单独存储标签字段，避免数据重复与不一致。`usage_count` 字段在素材新增、更新、删除或移除标签时同步维护，用于支持热门标签统计。

### 4.2 素材检索流程

素材检索需要同时支持关键词、分类和标签等多条件组合查询，基本流程如下：

1. 用户在前端输入关键词，并可选择一个或多个分类、标签筛选条件；
2. 前端将查询条件封装为请求参数，请求 `/api/v1/materials` 接口；
3. 后端根据关键词在 `name`、`content` 等字段上进行模糊匹配；
4. 根据 `category_id`、`material_tags` 关联表对分类、标签进行过滤；
5. 使用分页参数 `page`、`page_size` 控制返回结果数量；
6. 返回素材列表及总数，前端展示并支持继续翻页与筛选调整。

### 4.3 缓存策略（素材库相关）

为减轻数据库压力、提升常用数据访问性能，素材库相关的缓存策略建议如下：

- **热门素材列表缓存**：
  - Key 示例：`materials:hot:{date}`；
  - 内容：当日曝光/使用次数最高的若干条素材 ID 列表；
  - 过期时间：24 小时，次日自动失效重新统计。
- **热门标签缓存**：
  - Key 示例：`tags:hot`；
  - 内容：按照 `usage_count` 排序的前 N 个标签；
  - 过期时间：1 小时，通过定时任务或写入时触发刷新。
- **最近使用素材缓存**：
  - Key 示例：`materials:recent:{user_id}`；
  - 内容：用户最近使用的素材 ID 列表（如最近 20 条）；
  - 过期时间：7 天，在用户继续使用素材时自动刷新。

缓存击穿/失效时，统一回源 MySQL 查询，并按上述规则回写 Redis。

```sql
CREATE TABLE records (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    title VARCHAR(255),
    content TEXT,
    platform ENUM('douyin', 'xiaohongshu', 'wechat') NOT NULL,
    status ENUM('draft', 'published', 'archived') DEFAULT 'draft',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    INDEX idx_user_id (user_id),
    INDEX idx_platform (platform),
    INDEX idx_status (status),
    INDEX idx_created_at (created_at)
);
```
#### 4.1.7 版本表 (versions)
```sql
CREATE TABLE versions (
    id INT AUTO_INCREMENT PRIMARY KEY,
    record_id INT NOT NULL,
    version INT NOT NULL,
    content TEXT,
    is_ai_generated BOOLEAN DEFAULT TRUE,
    created_by INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (record_id) REFERENCES records(id) ON DELETE CASCADE,
    FOREIGN KEY (created_by) REFERENCES users(id) ON DELETE SET NULL,
    INDEX idx_record_id (record_id),
    INDEX idx_version (version)
);
```
#### 4.1.8 统计表 (statistics)
```sql
CREATE TABLE statistics (

    content_count INT DEFAULT 0,

    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
```
