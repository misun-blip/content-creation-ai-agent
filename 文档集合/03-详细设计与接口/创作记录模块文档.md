## 数据结构

### Record（创作记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | integer | 记录唯一 ID |
| user_id | integer | 所属用户 ID |
| title | string | 标题，最大 200 字符 |
| platform | string | 平台，可选值：`douyin` / `xiaohongshu` / `wechat` / `bilibili` |
| content | string \| null | 当前内容（与最新版本保持同步） |
| created_at | string | 创建时间，ISO 8601 格式 |
| updated_at | string | 更新时间，ISO 8601 格式 |
| versions | Version[] | 所有版本列表（详情接口返回） |

### Version（版本）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | integer | 版本唯一 ID |
| record_id | integer | 所属记录 ID |
| version_number | integer | 版本号，从 1 开始递增 |
| content | string | 该版本的内容 |
| change_note | string \| null | 修改说明 |
| created_at | string | 创建时间，ISO 8601 格式 |

### 通用响应结构

**成功响应**

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

**分页响应**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "items": [],
    "total": 0
  }
}
```

**失败响应**

```json
{
  "code": 404,
  "message": "创作记录不存在"
}
```

## 一、创作记录

### 1. 获取记录列表

获取当前登录用户的创作记录列表，支持关键词、平台、时间范围检索，结果按创建时间倒序排列。

**请求**

```
GET /api/v1/records/
```

**Query 参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyword | string | 否 | 标题关键词，模糊匹配 |
| platform | string | 否 | 平台筛选：`douyin` / `xiaohongshu` / `wechat` / `bilibili` |
| start_date | string | 否 | 开始日期，格式 `YYYY-MM-DD` |
| end_date | string | 否 | 结束日期，格式 `YYYY-MM-DD` |
| page | integer | 否 | 页码，默认 `1`，最小 `1` |
| page_size | integer | 否 | 每页条数，默认 `10`，范围 `1~100` |

**请求示例**

```
GET /api/v1/records/?keyword=抖音&platform=douyin&start_date=2026-01-01&end_date=2026-02-22&page=1&page_size=10
```

**响应示例**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "items": [
      {
        "id": 1,
        "title": "2026年营销热点趋势分析",
        "platform": "douyin",
        "version_count": 3,
        "created_at": "2026-02-12T10:30:00",
        "updated_at": "2026-02-12T12:30:00"
      }
    ],
    "total": 1
  }
}
```

---

### 2. 创建记录

创建一条新的创作记录。若请求体中包含 `content`，系统会自动创建版本号为 `1` 的初始版本。

**请求**

```
POST /api/v1/records/
Content-Type: application/json
```

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| title | string | 是 | 标题，最大 200 字符 |
| platform | string | 是 | 平台，可选值见上方说明 |
| content | string | 否 | 初始内容，若提供则自动创建 v1 版本 |

**请求示例**

```json
{
  "title": "抖音直播带货脚本",
  "platform": "douyin",
  "content": "开场白→产品介绍→痛点引入→限时优惠→催单话术"
}
```

**响应示例**

```json
{
  "code": 200,
  "message": "创建成功",
  "data": {
    "id": 8,
    "user_id": 1,
    "title": "抖音直播带货脚本",
    "platform": "douyin",
    "content": "开场白→产品介绍→痛点引入→限时优惠→催单话术",
    "created_at": "2026-02-22T13:00:00",
    "updated_at": "2026-02-22T13:00:00",
    "versions": [
      {
        "id": 1,
        "record_id": 8,
        "version_number": 1,
        "content": "开场白→产品介绍→痛点引入→限时优惠→催单话术",
        "change_note": "初始版本",
        "created_at": "2026-02-22T13:00:00"
      }
    ]
  }
}
```

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| record_id | integer | 记录 ID |

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "user_id": 1,
    "title": "2026年营销热点趋势分析",
    "platform": "douyin",
    "content": "2026年短视频营销呈现出三大核心趋势……",
    "created_at": "2026-02-12T10:30:00",
    "updated_at": "2026-02-12T12:30:00",
    "versions": [
      {
        "id": 1,
        "record_id": 1,
        "version_number": 1,
        "content": "2026年短视频营销趋势初稿。",
        "change_note": "初始版本",
        "created_at": "2026-02-12T10:30:00"

      {
        "id": 2,
```

| 状态码 | 说明 |

| 404 | 记录不存在或不属于当前用户 |

### 4. 更新记录

更新记录的基本信息（标题、平台、内容）。此操作**不会创建新版本**，如需保留历史，请使用版本管理接口。

**请求**

```
PUT /api/v1/records/{record_id}
Content-Type: application/json
```

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| record_id | integer | 记录 ID |

**请求体**（所有字段均为可选，仅传入需要修改的字段）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| title | string | 否 | 新标题，最大 200 字符 |
| platform | string | 否 | 新平台 |
| content | string | 否 | 新内容 |

**请求示例**

```json
{
  "title": "抖音直播带货脚本 2.0"
}
```

**响应示例**

```json
{
  "code": 200,
  "message": "更新成功",
  "data": {
    "id": 1,
    "user_id": 1,
    "title": "抖音直播带货脚本 2.0",
    "platform": "douyin",
    "content": "开场白→产品介绍→痛点引入→限时优惠→催单话术",
    "created_at": "2026-02-22T13:00:00",
    "updated_at": "2026-02-22T14:00:00",
    "versions": []
  }
}
```

---

### 5. 删除记录

删除指定记录，同时**级联删除**该记录下的所有版本，此操作不可恢复。

**请求**

```
DELETE /api/v1/records/{record_id}
```

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| record_id | integer | 记录 ID |

**响应示例**

```json
{
  "code": 200,
  "message": "删除成功",
  "data": null
}
```

```json
{
  "code": 200,
```

### 2. 创建新版本

为指定记录保存一个新版本，版本号自动在当前最大版本号基础上 +1。同时会将记录的 `content` 字段同步更新为本次版本内容。

**请求**

```
POST /api/v1/records/{record_id}/versions
Content-Type: application/json
```

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| record_id | integer | 记录 ID |

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| content | string | 是 | 新版本内容 |
| change_note | string | 否 | 修改说明 |

**请求示例**

```json
{
  "content": "开场白→产品介绍→痛点引入→解决方案→限时优惠→催单话术→用户见证",
  "change_note": "增加用户见证环节"
}
```

**响应示例**

```json
{
  "code": 200,
  "message": "版本创建成功",
  "data": {
    "id": 3,
    "record_id": 1,
    "version_number": 3,
    "content": "开场白→产品介绍→痛点引入→解决方案→限时优惠→催单话术→用户见证",
    "change_note": "增加用户见证环节",
    "created_at": "2026-02-22T14:00:00"
  }
}
```

### 4. 回滚版本

将记录回滚到指定版本。系统会以目标版本的内容创建一个新版本（版本号继续递增），并将记录的 `content` 同步更新，**不会删除任何历史版本**。

**请求**

```
POST /api/v1/records/{record_id}/versions/{version_id}/restore
```

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| record_id | integer | 记录 ID |
| version_id | integer | 要回滚到的目标版本 ID |

**响应示例**

> 假设当前最新版本为 v3，回滚至 v1 后，系统创建 v4，内容与 v1 相同。

```json
{
  "code": 200,
  "message": "回滚成功",
  "data": {
    "id": 4,
    "record_id": 1,
    "version_number": 4,
    "content": "初稿内容",
    "change_note": "回滚自版本 v1",
    "created_at": "2026-02-22T15:00:00"
  }
}
```

**错误响应**

| 状态码 | 说明 |
|--------|------|
| 404 | 目标版本不存在 |

---

### 5. 删除版本

删除指定版本。每条记录至少保留一个版本，若当前只剩一个版本则拒绝删除。

**请求**

```
DELETE /api/v1/records/{record_id}/versions/{version_id}
```

**路径参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| record_id | integer | 记录 ID |
| version_id | integer | 版本 ID |

**响应示例**

```json
{
  "code": 200,
  "message": "版本删除成功",
  "data": null
}
```

**错误响应**

| 状态码 | 说明 |
|--------|------|
| 400 | 至少需要保留一个版本，拒绝删除 |
| 404 | 版本不存在 |

## 三、导出

### 1. 导出 CSV

将当前用户的创作记录导出为 CSV 文件，支持与列表接口相同的筛选参数。文件编码为 **UTF-8 BOM**，可直接用 Excel 打开，时间字段为北京时间（UTC+8）。

**请求**

```
GET /api/v1/records/export/csv
```

**Query 参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyword | string | 否 | 标题关键词 |
| platform | string | 否 | 平台筛选 |
| start_date | string | 否 | 开始日期，格式 `YYYY-MM-DD` |
| end_date | string | 否 | 结束日期，格式 `YYYY-MM-DD` |

**请求示例**

```
GET /api/v1/records/export/csv?platform=douyin&start_date=2026-01-01
```

**响应**

返回二进制文件流，浏览器将自动触发下载。

```
Content-Type: text/csv; charset=utf-8-sig
Content-Disposition: attachment; filename="records_20260222133000.csv"
```

**CSV 字段说明**

| 列名 | 说明 |
|------|------|
| ID | 记录唯一 ID |
| 标题 | 记录标题 |
| 平台 | 所属平台 |
| 版本数 | 该记录的版本总数 |
| 创建时间 | 格式 `YYYY-MM-DD HH:MM:SS`（北京时间） |
| 更新时间 | 格式 `YYYY-MM-DD HH:MM:SS`（北京时间） |
| 内容 | 当前版本内容，换行符替换为空格 |

> **注意：** 此接口需要在请求头中携带 `Authorization: Bearer <token>`，直接在浏览器地址栏访问会返回 401。前端应使用 axios 等 HTTP 客户端发起请求并设置 `responseType: "blob"` 来触发下载。

## 错误码说明

| HTTP 状态码 | code | 说明 |
|-------------|------|------|
| 200 | 200 | 请求成功 |
| 400 | 400 | 请求参数错误（如：至少需要保留一个版本） |
| 401 | 401 | 未认证，token 缺失或已过期 |
| 403 | 403 | 无权限访问该资源 |
| 404 | 404 | 资源不存在 |
| 422 | 422 | 请求体参数校验失败 |
| 500 | 500 | 服务器内部错误 |
